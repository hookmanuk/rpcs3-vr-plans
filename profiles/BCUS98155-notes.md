# MotorStorm: Pacific Rift (BCUS98155 v01.00)

Profile `bin/vr_profiles/BCUS98155.json` (generated by Matt, 2026-09-25), patch `bin/patches/BCUS98155_patch.yml`
(copy: `profiles/BCUS98155-patch.yml`), config `custom_configs/config_BCUS98155.yml` (Matt's). Evidence
`evidence/motorstorm/`. Work of 2026-09-30 (night); desktop only, not run in the headset.

## Frame rate (patch "Unlocked frame rate (VR)", on by default)

The community "60 FPS" (NOP at `0x435d1c`: the game no longer sets its flip interval to 2 vblanks) plus
"Variable FPS" (`li r6,1` at `0x435f9c`: the clock object steps by measured real time instead of a fixed tick).
Flat at Vblank 90: 90 FPS in a race; memclock over 12 s: 689 clock-like floats at 1.00x wall time. The profile
had `max_fps 30`, `vblanks_per_frame 2` (generated at the locked rate); now `max_fps 0`, `default_fps 0`, so the
vblank follows the headset. Community caveat: slower movement through water above 60 FPS (not checked).

## Picture vs flat

- Paused, same frame: flat and the left eye have equal mean colour; the per-pixel differences are edges only
  (stereo parallax) and animated water (`flat-vs-stereo-same-moment.png`). Yaw 25 and pitch 35 audits in a race
  are clean: world, car, shadows, sky and debris turn together, HUD fixed.
- **Dynamic resolution** (patch "Disable Dynamic Resolution Scaling (VR)", on): the game lowers its render
  resolution when frames take long. One early stereo frame, with it on, was soft and washed out against flat
  (`stereo-before-drs-off.png`); with stereo costing more RSX time it would drop resolution in the headset.
- **Motion blur** (patch "Disable Motion Blur (VR)", on): camera motion blur smears on head turns.
- **Write Color Buffers must stay on.** Off, the picture is overexposed (`wcb-off-overexposed.png`): the game
  reads a luminance target back (8x8 at `0xc7f70100`) for exposure.

Not found on the desktop: any other stereo-only difference. If Matt still sees one in the headset, it needs a
description of what and where.

## Performance

Flat at 100%: 88-90 FPS at the race start with the pack. Stereo was 29-44 there, RSX thread 100% busy with the
GPU ~24% used. A quarter of the RSX thread was `cached_texture_section::flush` from `upload_texture`: every
frame the game samples render target memory as plain textures (640x480 `0xc7b85480`, 640x360 `0xc243ab00`,
320x180 `0xc7f37d00`, the 8x8 exposure target), so the texture cache wrote the targets back and waited for
the GPU to finish both eyes' queued work.

Fork change (generic): `texture_cache::flush_set` records the ranges it had to transfer; in stereo
`VKGSRender::prepare_rtts` adds them to the early-copy list GT5 introduced (sections copied as soon as their
surface is left, then submitted). Log: "VR: render target memory ... copied early from now on". Flush time on
the RSX thread 24% -> 13%; stereo race start 29-44 -> 43-63 FPS, 70-90 once the pack spreads.

- Multithreaded RSX: no clear change (47-63).
- 300% on the headset path: 35-53 FPS in a race, GPU 68%.
- Still open: the remaining flush waits (the early copy still waits for the right eye's work of the same
  pass), and the per-draw stereo cost (multiview).

## Driving it unattended

Keyboard pad from the template. The key hook drops presses while a menu animates in, so the route needs
checking with screenshots. Title: Return, Return (attract video), X, main menu: Down, X (Wreckreation). The
cursor starts on ONLINE and the next Down is often lost; if the "No PlayStation Network account" dialog opens,
X, Down. Then X (Free-Play), X (opponents), X (start), Right x3 (rally car), X, X, X. At Vblank 90 the same keys
sometimes end in the Festival (Earth Zone tickets); Left, Left, X there also gives a race after its intro.
Pause > Restart Race needs Up on the confirmation (default is No).

Headset-path screenshots (`RPCS3_VR_SHOT` without `RPCS3_OPENXR=0`) of 3D frames come out upside down: the
display buffer holds the headset-remapped frame. Menus without camera draws are upright.
