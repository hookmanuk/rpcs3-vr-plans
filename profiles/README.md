# VR profile format (schema 1)

A game gets VR when `rpcs3/bin/vr_profiles/<TITLE_ID>.json` exists and is valid. The file holds
only what the renderer reads; this page explains the fields. Loader:
`rsx::vr::load_title_profile()` in `rpcs3/Emu/RSX/Capture/rsx_camera_probe.cpp`. An invalid file is
logged (field, line, column) and the game runs in 2D; unknown keys are logged as warnings.

Measurements and reasoning behind WipEout's values:
`plans/profiles/BCES00664-evidence.json` (and `plans/evidence/gate4/analysis-stereo-fit.txt`,
`tools/fit_stereo.py`).

| Field | Required | Meaning |
|---|---|---|
| `schema` | yes | Format version; must be `1`. |
| `title_id` | yes | Must match the file name. |
| `app_version` | no | Game version the values were fitted on; a mismatch is logged, not rejected. |
| `name` | no | The game's name, shown in the VR Frame Rate setting (needed for collections, where one title ID holds several games). The generator writes it. |
| `matrix_layout` | yes | How a 4-slot matrix is stored. `row_vectors`: `clip = v.x*c[b] + v.y*c[b+1] + v.z*c[b+2] + c[b+3]`, so each slot is one row; column 0 gives clip.x, column 3 gives clip.w (WipEout). `column_vectors`: `clip[i] = dot(c[b+i], v)`, the transpose, as PSGL/Cg DP4 code does (Pure); the renderer transposes such a block, runs the same math, and writes it back. A DP4 program may omit the z slot and take clip z from the w row (Pure's sky: `c[26]`, `c[27]`, `c[29]`); the block is then used with z = w. | `column_vectors_xyw`: a DP4 camera of three slots, clip x, y and w at `b`, `b+1`, `b+2`, with z derived by the shader (NFS Most Wanted: `c[212..214]`, z parameters in `c[215]`).
| `camera_blocks` | yes | Vertex constant slots of 4-slot camera matrices, tried in order. The first whose column 3 is not `(0,0,0,1)` (i.e. perspective) is the draw's camera. WipEout: 256 is world-view-projection on its single-matrix route; 260 is view-projection on its two-matrix route, where 256 is an affine world matrix. | An entry can also be an explicit list of the block's 4 slots when they are not contiguous: MGS4's camera-relative draws use `[0, 1, 2, 7]` (translation row in `c[7]`).
| `row_vector_blocks` | no | Camera (or HUD) blocks stored in the `row_vectors` layout whatever `matrix_layout` says. Bayonetta: scene `column_vectors` `c[8]`, sprites `row_vectors` `c[24]`: `[24]`. The generator writes it for a row-layout second camera. |
| `linked_camera_blocks` | no | Blocks holding another view of the same camera, read beside it: Bayonetta's motion-vector pass keeps the previous frame's view-projection in `c[36..39]` next to the camera `c[8..11]`. They get the camera block's clip-space eye transform (X = M^-1 * M_eye), so the velocities stay the game's. Without it, head rotation and the headset FOV changed only the current matrix and the motion blur smeared every character (headset only; the desktop shift is too small to see). The generator writes it. |
| `camera_palette` | no | `[first, last]`: a palette of per-bone **clip** matrices beside the camera block (4 slots each, `first`, `first + 4`, ... `last`), picked per vertex through the index register. Each block in the range that has the camera's projection (clip z = a x clip w + b, as the camera block) gets the camera block's clip-space eye transform (X = M^-1 x M_eye, as `linked_camera_blocks`); other data in the range is left alone. Kingdom Hearts Final Mix: rigid skinning with full MVPs at `c[256 + 4k]`, `[260, 444]`; without it only bone 0 moved and characters stayed head-locked with stretched limbs. Found by reading a skinned program (`_fetch_constant(256 + a0.x)`). The generator writes it when 10+ indexed draws have 2+ blocks after the first camera block with its projection (KH Final Mix: `[260, 444]`; Dragon's Dogma's affine bones: none). |
| `require_rigid_camera` | no | `true`: a camera block counts only if its clip x, y and w directions are mutually orthogonal (within 0.1). Pure: keeps `c[39..42]`, which holds unrelated data in a post-process quad, from being taken as a camera. Off for WipEout and Ridge Racer 7, whose per-object matrices can be non-uniformly scaled (with it on, RR7's wheels and light glows stayed head-locked). |
| `nonrigid_camera_blocks` | no | Camera blocks accepted without the `require_rigid_camera` test, for programs whose block folds in an object's non-uniform scale. Demon's Souls: `[4]`, the fog gate distortion layer (`c[4..7]`, clip y and w nearly parallel); rejected, it kept the game camera and showed a second picture of the scene inside the portal. |
| `require_camera_aspect` | no | `true`: a camera block must also project square pixels at the output aspect (|clip y| / |clip x| within 10%). For engines whose camera base varies with the number of object-matrix slots before it (inFamous 1 and 2), where `camera_blocks` lists overlapping bases and some other block can pass the perspective and rigid tests. The generator sets it when it keeps overlapping blocks. |
| `camera_slots_read_directly` | no | `true`: in programs that index their constants (bone palettes), which get the whole constant bank, a camera block counts only if the program reads its slots directly. Without it, bone matrices at a camera block's slots can pass the perspective test (Dragon's Dogma: bones at `c[3]`, its static camera). The generator writes it whenever it sampled such programs (it samples them by their direct slots). |
| `game_camera_programs` | no | Vertex-program ucode hashes whose draws keep the game camera in both eyes (no head transform or stereo). For helper passes that break when moved. Try candidates live with probe `gamecam=<hash>[+<hash>]`. |
| `output_aspect_tolerance` | yes | A draw is a camera view only if its render target's aspect is within this fraction of the output aspect. WipEout: excludes the 512x256 shadow cascades, whose perspective 260 block is shared between eyes. |
| `camera_target_aspect` | no | Aspect of the render targets that hold camera views when it is not the output's. MGS4 renders its 16:9 picture anamorphically into 1024x768 targets: 1.33333. The generator sets it from the target size with the most camera draws. The HUD box also applies on output-aspect targets (Anarchy Reigns: scene 1024x720, HUD drawn at 1280x720). |
| `camera_position.slot` | no | Slot holding the camera world position. Each eye moves it by `eye_baseline / 2` along camera right on every draw that reads it (shadow cascades included). |
| `camera_position.eye_baseline` | yes | The game's native distance between the eyes, in world units. Also the world scale for head tracking: `eye_baseline` units = the viewer's IPD. |
| `stereo.formula` | yes | Only `clip_x_shear`: `clip.x += sep * (clip.w - conv)` per eye, `sep = -/+ per_eye_separation`. The headset path keeps only the translation term (`-sep * conv`). |
| `stereo.per_eye_separation`, `stereo.convergence` | yes | The default shear. |
| `stereo.by_target_width[]` | no | Overrides for render targets exactly `output_width / output_width_divisor` wide. WipEout's 640x360 pass uses 0.75x the full shear, not 0.5x. |
| `stereo.eye_offset` | no | `"baseline"`: each eye is offset by `eye_baseline` in world units, taken from each camera matrix's own scale, instead of the fixed clip-space shear. The shear equals `eye_baseline` only at the projection it was measured with: a patch that widens the game's view (SotC's Wider view) made the same shear a much wider eye distance, so the world looked tiny. Use it with any view-widening patch. The generator always writes it. `"baseline_per_w"`: the same, per unit of the matrix's clip-w row, so an object scale folded into per-object MVPs cancels and `eye_baseline` is in view units for every object. For games whose camera blocks are per-object MVPs with different scales (Jak 1: w-row scales 0.016 to 1; the plain baseline left most of the world flat). The generator writes it when the w-row scale varies over 2x; check `eye_baseline` against a known size (Jak 1: 0.128, a view unit ~0.5 m). |
| `screen_space.orthographic_block` | no | An output-aspect draw with no perspective camera block but an orthographic matrix here is HUD/menu, drawn in the fixed HUD box. |
| `screen_space.orthographic_block_layout` | no | `"row_vectors"`: the HUD block is read in rows although the camera layout is columns. No shipped profile needs it (Bayonetta's HUD looked like a row-layout case but reads `c[8..11]` with DP4 like its scene; setting it left the HUD head-locked). Check the HUD program's shader before using it. |
| `screen_space.bare_projection` | no | `true`: a perspective camera block with no view rotation or translation folded in is also screen space (WipEout's main-menu particle cloud). |
| `screen_space.depth_offset_projection` | no | `true`: a perspective camera block with no view rotation and only a translation along the view axis (`w = z + d`, d != 0) is screen space too: geometry drawn in the camera's own space at a fixed depth. Blur's 3D HUD (`w = z + 42.65`). Separate from `bare_projection` because Blur's deferred light volume is an exact bare projection that must follow the head. |
| `screen_space.offaspect_projection` | no | `true`: a bare projection (as for `bare_projection`) whose square-pixel aspect (|y| / |x| scale) is more than 10% off the output's is screen space and goes into the HUD box; one at the output aspect stays the camera. For engines that transform vertices into view space themselves, so the scene and the HUD are both bare projections in the same slots. God of War HD: scene 16:9, HUD 4:3 (`c[256]`). Headset path only. The generator sets it when every camera draw is a bare projection and draws without depth test use another aspect. |
| `game_camera_target_widths` | no | Render targets exactly this wide (guest pixels) keep the game's camera in both eyes: views that are not the player's own. Blur's rear-view mirror (320x180). |
| `screen_space.rotation_only_passthrough` | no | `true`: a draw **without depth test** whose camera block has no translation at all (clip w = view z) is a full-screen pass building view rays from it (inFamous 2's final composite). It follows head rotation but gets no eye offset, head translation or stereo shear. The depth-test condition matters: inFamous 2 also draws world geometry camera-relative with such blocks. |
| `screen_space.preprojected_programs` | no | List of vertex-program ucode hashes (hex strings, as in inspector captures) whose positions the game projected itself (ICO's flames: NDC with w = 1). Their draws get `B^-1 * B_eye` of the latest camera block for each eye, so they follow the head, eye offset and FOV remap like the camera draws. |
| `screen_space.hud_skips_passes` | no | `true`: draws reading the `orthographic_block` that sample a colour render target are full-screen passes (post-processing), left as drawn. Demon's Souls draws its HUD and its post passes with the same `c[0]`; without this its scene composite went into the HUD box. The generator writes it when passes read the HUD block. Only a view-shaped target makes a pass (a camera target, a display buffer, or the output's or `camera_target_aspect`'s shape): a HUD draw sampling a small mask or atlas the HUD drew stays HUD (Anarchy Reigns' 256x256 gauge mask). A `row_vectors` HUD block may leave out the z slot (a 2D HUD reading `c[0]`, `c[1]`, `c[3]`); it is bound with a zero z row. In the fixed HUD box, draws without depth test get `z = w/2` (a HUD on the far plane was clipped). |
| `screen_space.passthrough_hud` | no | `true`: HUD and menus drawn with no matrix at all (positions straight out of the vertex shader; ICO's pause menu) go into the HUD box: a draw that uses no camera block, samples only ordinary textures and targets a full-frame buffer no camera draw wrote this frame. Not detected by the generator: set it when the menus fill the view. |
| `screen_space.hud_programs` | no | Vertex-program ucode hashes whose matrix-less draws are HUD even into a target camera draws also wrote (SotC draws title, menu and font glyphs straight into the scene's final image). The other `passthrough_hud` checks still apply. |
| `screen_space.hud_keep_depth` | no | `true`: HUD-box draws in fixed mode keep the game's depth (z scaled by w'/w), for games whose HUD depth-tests its own layers (SotC's menus reordered and vanished when leaning in). Off by default: it broke Ico's HUD box. |
| `hud_depth` | no | Metres (1-10) from the eyes to the HUD box when the HUD Depth setting is Auto (its default); a value set in the settings wins. Unset = 2 m. Killzone HD: 4 (the aiming reticule sat too close at 2 m). |
| `keep_rendered_display_buffers` | no | `true`: in stereo, memory copies (NV0039) into a display buffer are skipped. For games that round-trip the finished frame through main memory: with Read Color Buffers the left eye was reloaded at 1x while the right eye kept the scaled frame (Killzone HD). |
| `hidden_draws` | no | List of `{ "name": "...", "program": "<vertex ucode hash>", "texture": "<width>x<height>", "hidden": true\|false }`: matching draws (vertex program + texture 0 size) are skipped while VR is enabled; `"hidden": false` shows the effect again. For effects that look bad in the headset. Killzone HD: film grain (`4948caa7790a8473`, 128x128), hidden by default. |
| `screen_space.scaled_draws` | no | List of `{ "program": "<vertex ucode hash>", "texture": "<width>x<height>", "scale": <factor> }`: HUD draws resized about the game screen's centre before the HUD box (1 = as drawn). Killzone HD: reticule at 0.25. |
| `screen_space.unboxed_draws` | no | List of `{ "program": "<vertex ucode hash>", "texture": "<width>x<height>" }`: draws with that vertex program and texture 0 of that size stay out of the HUD box (full view). For full-screen overlays drawn with the HUD matrix and HUD shaders: Killzone HD's film grain (`4948caa7790a8473`, 128x128), which boxed made a grey panel. Find them with probe `unboxfp=<fragment program session id>` (from an inspector capture), which logs the hash and size. |
| `screen_space.boxed_cameras` | no | List of clip-w rows `[x, y, z, w]` (the camera block's input weights for clip w, after any transpose): camera draws whose block has that w row (within 0.1%) go into the HUD box with the game's camera, headset view only. For 3D menu elements drawn with a fixed menu camera. Ratchet & Clank 1: its pause-menu panels use an axis-aligned camera with clip w = x - 256, `[[1, 0, 0, -256]]`. Replaced `boxed_camera_programs` (by vertex program), which boxed R&C 1's whole level: the same two programs draw the world, and the headset showed it as a flat window. |
| `screen_space.screen_frame_draws` | no | Same `{program, texture}` form as `unboxed_draws`: a frame containing one of these draws is shown whole on the fixed screen with the game's own camera. For a menu composed of a 3D model and 2D layers that the headset view pulls apart. God of War 1: its logo draw (`a3b1455d9ebdd381`, 1024x256) on the main menu. List a draw only that screen makes. |
| `screen_space.clear_outside_box` | no | `true`: in a frame whose first write to a display buffer is a HUD-box draw (boxed through the orthographic block), the shown region is cleared first. For 2D screens whose own full-screen background is boxed, so nothing is written outside the box: Killzone HD's main menu glow pass (downsample of the whole buffer added back onto it) fed on itself there up to white. Any unboxed draw into the buffer that frame (a scene drawn straight into it) prevents the clear. Off by default: a scene that reaches the display buffer by blit is not counted and would be wiped. |
| `screen_space.hud_display_buffers_only` | no | `true`: only draws into a display buffer (a flipped frame buffer's address at the display buffer's size, or a depth-only draw that size) take the HUD box, and with `hud_skips_passes` a pass is a draw sampling a screen-sized texture (scene, display buffer, full-screen buffer); smaller reads are HUD art. Before the first boxed draw into a display buffer no pass or full clear covered in a frame, the shown region is cleared (2D menus that never clear). Gran Turismo 5: font atlas in a 2048x1080 target, shadow cascades in the hidden display buffer's memory, icon backgrounds cut from a 2048-wide blur buffer. |
| `screen_space.hud_box_after_shader` | no | `true`: the HUD box is applied to the vertex shader's output position (the `passthrough_hud` path) instead of to the orthographic block, so varyings the shader derives from the projected position (GT5's text clip masks; Anarchy Reigns' gauge, which looks up a 256x256 mask at its clip position) stay with the geometry. The generator writes it when HUD draws sample a small render target. Also boxes perspective draws straight into a display buffer (GT5's menu cards). |
| `screen_space.output_pixel_draws_not_hud` | no | `true`: draws whose orthographic block maps output pixels 1:1 (`c.x = 2/output width`) are screen fills and stay as drawn. GT5 lays out its HUD in 1920x1080 units but clears, fades and writes text coverage in 1280x720 pixels; boxed, those broke all menu text and left trails. |
| `screen_space.subviewport_cameras_in_box` | no | `true` (needs `hud_box_after_shader`): camera draws through a viewport smaller than their view target go into the HUD box with the game's camera, and a scissored clear through such a viewport moves with them. GT5's rear-view mirror (448x86 at (416,42) of the scene). |
| `screen_space.frames_without_3d_as_screen` | no | Unset (default since 2026-10-01): frames with no camera draws whose displayed buffer holds no 3D content (render targets carry it from camera draws, through sampling and copies) go on the fixed screen: splash screens, videos, 2D menus. A paused game re-showing its last 3D frame stays in the headset view. `true`: every frame without camera draws (ICO, Demon's Souls, God of War, Dante's Inferno's pause menu). `false`: never (WipEout, Pure, Ridge Racer 7, Bayonetta, Killzone HD keep their tested behaviour). |
| `reference_screen_width` | no | Width in metres of the screen the game's stereo is tuned for (WipEout: a 24" TV, 0.53 m). Fixed Screen scales separation by reference / window width so far objects keep the same physical disparity. 0 or absent: no scaling. |
| `game_frame_ms_f32` | no | Guest floats holding milliseconds per frame, written with 1000/fps like `game_frame_time_f32` (only over a value from 2 to 100). Dante's Inferno steps its clock by whole frames of `[0x119ecb4]` (16.68 ms), at least one a frame. |
| `texture_redirects` | no | `[{"from": "<guest address>", "to": "<render target address, 0xc...>"}]`: while stereo renders, a texture read at `from` (a main-memory copy that the SPUs post-process, which only ever holds the left eye) reads the render target at `to` instead, per eye. Puppeteer: scene `0xc0750000` -> SPU EDGE post -> `0x399c0000`. Skips the SPU effects in VR. Find it in an inspector capture: a blit from the scene target into main memory, then a draw sampling a main-memory texture of the same size. |
| `max_fps` | yes (release) | The most the game works at in VR with its default patches (ICO: 30); the VR **Frame Rate** setting offers nothing above it. `0` = no maximum: the game keeps real-time speed at any vblank rate (WipEout, Pure), so Unlimited runs the vblank at the headset's rate. **Missing = no maximum**, so only a game shown to keep real-time speed should leave it out; the profile generator writes the measured rate. Replaces `match_headset_refresh_rate`. |
| `default_fps` | no | What Frame Rate "Default" runs: a rate current hardware reaches. `0` = the headset's refresh rate (WipEout, Pure). Missing = `max_fps`, or 60 without one. Must not exceed `max_fps`. Games of one collection share a configuration, so each profile sets its own default (ICO 30, SotC 60). |
| `vblanks_per_frame` | no | Vblanks per game frame (ICO: 2): the emulated vblank runs at frame rate x this. Default 1. The generator measures it. |
| `video_vblank_rate` | no | While the game has any video decoder open (cellVdec), the emulated vblank runs at most this fast, with or without VR (`0`/unset = no cap). Killzone HD: `60`; its movie player (libsail) stops taking decoded frames at 90 Hz, so the intro stayed black until skipped. The log says "video decoder open: vblank 60 Hz" / "closed". |
| `zcull_approximate` | no | `true`: while VR renders, ZCULL (occlusion-query) reports work as with ZCULL Accuracy "Approximate": any visible pixel reports as fully visible, and RPCS3 stops waiting for exact counts. For games that read their occlusion queries synchronously: in stereo each wait covers both eyes' GPU work. Dragon's Dogma: RSX thread 13.9 -> 7.8 ms per frame at 72 Hz (4K per eye). Flat play and the user's setting are unchanged. Check flares/glows that might scale with the visible pixel count. |
| `reproject_older_frames` | no | `true`: the game builds effects across frames from full-screen buffers (ICO's glow and previous-frame blend, SotC); head pose is taken at frame boundaries and older-pose buffers are turned to the current pose. Off by default: in Pure it caused flashes, a bright square and the paused frame floating in space. |
| `occlusion_depth_readback` | no | `["0xADDR:0xSIZE", ...]`: guest memory the game copies its depth buffer into for CPU/SPU occlusion culling (SotC). In stereo that depth is the eye's, so reads there return far depth (nothing is occlusion-culled) without waiting for the GPU. |
| `game_refresh_rate_f32` | no | Guest floats holding the game's display refresh rate, written every frame with the effective vblank rate so the game keeps real-time speed at the headset's rate. `"0xADDR"`, or `"[0xPTR]+0xOFF"` for a pointer plus offset. Only overwrites a value between 20 and 1000. Pure: `["[0x1050300]+0x14"]` (PSGL device refresh). |
| `game_frame_time_f32` | no | Guest floats holding the game's seconds per frame (1/60 in a 60 FPS game), written with 1/fps (fps = effective vblank rate / `vblanks_per_frame`) so a frame-locked game's physics keeps real-time speed. Same address forms as `game_refresh_rate_f32`; only overwrites a value between 0.002 and 0.1. Ridge Racer 7: the 21 static 1/60 floats. |
| `game_frame_ms_u32` | no | Guest words holding milliseconds per frame (17 at 60 FPS), written with round(1000/fps); only overwrites 1-100. For words a game patch adds and reads (Ridge Racer 7's race timer). |
| `game_fps_u32` | no | Guest words holding frames per second, written with round(fps); only overwrites 10-1000. For game-patch code caves that turn a per-frame step into the real time of the frame from the vblank count (Ridge Racer 7: `floor(k*A/fps) - floor(k*(A-1)/fps)` ticks, k = 60, 1000 or 3000). |
| `resolution_scaled_constants` | no | `[{ "program": "<vertex ucode hash>", "slots": [466, 467] }]`: vertex constants holding texture-coordinate offsets (a pass's filter taps), divided by the resolution scale so the filter keeps its footprint in rendered pixels. Ridge Racer 7: its scene resolve averages three taps a quarter native pixel apart, which otherwise capped the scene's sharpness near 1x at any scale. |
| `fragment_constant_overrides` | no | `[{ "program": "<vertex ucode hash>", "constant": 0, "value": [0, 0, 0, 0] }]`: fragment constant `n` (as the shader reads it, `_fetch_constant(n)`) is replaced in every draw of that vertex program, which turns a post effect off by its strength constant. Use a vertex program only that pass draws. Demon's Souls: its depth-of-field composite (`73cbac9f`) blends in the blurred copy by `fc[0]`; the blur amount it scales grows with distance from the screen centre, so in the headset's wider view the floor and the top of the view were blurred, with doubled rocks. |
| `offaspect_player_views` | no | `true`: camera draws into off-aspect render targets whose projection has the output aspect follow the head like the scene (rotation, eye offset, headset FOV) but keep their viewport. For views the scene samples at its own screen position. Ridge Racer 7: road reflection tiles (128x128 in a 512x128 target); without it reflections followed the head. Off by default: other off-aspect targets keep the game camera. |
| `current_frame_copies` | no | `true`: the game composites the previous frame's scene with effects built from the current one (ICO: the scene double buffer left over from SPU MLAA, bloom from this frame). Each frame carries its own head rotation, so in the headset the two layers disagree (white glow trailing head turns). A blit whose source is a scene target drawn with an earlier pose reads its twin (same size, format, pitch) drawn in this frame. Also removes a frame of latency. Do not set it for games that read the previous frame on purpose (motion blur, frame blending). |
| `clip_space_scene_draws` | no | `true` (experimental): depth-tested draws into the scene that no camera block covers (object matrix folded in so the block is not rigid, another slot or layout, skinned from the whole constant bank) take the latest camera draw's eye transform `B^-1 * B_eye` after their own program. The object part of `B` cancels, so any draw through the same camera lands where the eye sees it. Draws that sample a colour render target (post-processing) and HUD draws are left alone. The generator sets it when camera blocks cover under 80% of depth-tested scene draws. Demon's Souls first triggered it (19%), but the real cause was camera blocks the generator could not see; with those found it covers 100% and the flag is not written. No shipped profile uses it. |

Not yet in the format: WipEout's infinity layers (sky/skyline) use convergence 0 natively and are
still drawn with the default rule (see the evidence file, `stereo.variants_seen`).

A game whose engine needs another `matrix_layout`, `stereo.formula` or screen-space test needs that
rule added in code under a new name; the loader rejects values it does not know.

**File name.** `bin/vr_profiles/<TITLE_ID>.json`, or `<TITLE_ID>.<executable>.json` for one game of a collection (lower-case executable file name without extension: `BCUS98259.shadow.json` for `Shadow.self`). The loader tries the executable-specific file first. The profile generator never overwrites an existing `<TITLE_ID>.json`; it writes the executable-specific name instead.
