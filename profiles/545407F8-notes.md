## Frame rate (free roam, parked by the first garage, uncapped)

| Build | FPS | Notes |
|---|---|---|
| D3D12 | 85-88 | game -O3 -msse4.1 |
| D3D12, game x86-64-v3 | 88-90 | |
| Vulkan | 63-67 | replay + submit 4.1-4.9 ms of the GPU thread's frame |

| Vulkan, FSI render targets | 56 | host render targets are the default and faster |
| Vulkan, 2x2 resolution scale | 64 | GPU cost is mostly fixed per frame |

- RTSS's counter shows presents, not game frames (37 where the game made 65): the FPS line in the log
  (`VulkanCommandProcessor::IssueSwap`) counts the game's swaps.
- The game thread waits ~50% on the GPU thread: D3D's swap throttle (sub_82419E98 waits at 0x8241A3F8 for the previous
  swap's fence, two swaps per presented frame); letting it run one swap further only moves the wait to the game's own
  resource fences (caller 0x82421D94). `--mcla_fence_probe=true` logs the waits.
- The GPU thread waits once a frame for the host GPU (frames in flight, 3.2-3.5 ms); GPU 3D engine 57-75% busy at
  720p. Occlusion queries off: no change.
- Profiling: `--mcla_profile=<file>` (sampling); `MCLA_PROFILE_RAW=1` writes module offsets so mcla.exe's PDB names
  the function (the guest attribution credits the nearest registered function: "sub_82788F80" was mcla_fence_spin).
