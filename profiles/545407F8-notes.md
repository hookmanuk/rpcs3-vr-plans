## VR (SDK branch `vr`, game branch `vr`; 2026-10-24)

Run: `mcla.exe --vr=true` (or `MCLA_VR=1`); on the simulator add `XR_RUNTIME_JSON=<simulator json> XRFG_DISABLE_OFXR_BRIDGE=1`. `MCLA_VR_STEREO=0`: mono
(the same picture in both eyes). `MCLA_VR_WORLD_SCALE`: game units per metre (1; RAGE units are metres).

- Camera (`src/vr_camera.cpp`): grcViewport::SetCameraMtx (sub_8217CE80) at 0x82312D3C is the frame's camera origin
  (update thread, matrices BCF25AD0/BCF25B10 for the two buffered viewports BCF25BF0/BCF25FE0); every later
  SetCameraMtx on those viewports re-reads the viewport's stored camera, so posing the origin call (a scratch copy,
  head rotation and position in camera space: rows right, up, back, position) poses them all. The render thread
  draws the buffer a frame later: the pose is kept per viewport and handed to the headset (vr::SetFramePose) at
  that viewport's grcViewport::Perspective (sub_8217D460) from 0x822E5EB8, which also gets the headset's fov
  (symmetric union of the eyes; tangents 1.376 x 1.390 on the simulator). The pose travels with VdSwap
  (OnGameSwap) to the GPU thread's swap packet (OnGpuSwap) and the frame's publication.
- Checking world lock: the simulator shows each eye's image as submitted (no reprojection), so a shot at a head turn
  should be the straight-ahead shot rotated by the turn, at the rendered fov. `vr/rotcheck.py A B axis eye l r u d`
  fits the angle by NCC.
- Stereo (`vr_twins.cpp`): the deferred command buffer replays twice per submission; the right eye's function table
  swaps every handle for its twin (images, buffers, views, framebuffers, descriptor sets, query pools). Twins:
  every allocation in memory the CPU can't see gets one of the same size, and resources bound to it are made again
  and bound at the same offset. Textures are the same in both eyes until loaded from GPU-written pages; descriptor
  sets get a twin only when written with an eye-dependent view or buffer. Sparse shared memory is off in stereo.
  Guest vertex shaders get a push constant: x += P00 * (+-baseline/2) where |w - 1| > 1/1024 (screen-space draws,
  W 1, stay put).

## Direct resolves (2026-10-27 evening, SDK `vr`)

A resolve's copy is a compute from the render target's image straight into the texture's image: no dump into the
EDRAM buffer, no resolve copy into the tiled scaled buffer, no untiling load, no scratch-buffer copy.
- `VulkanRenderTargetCache::VrDirectResolve` (render_target_cache.cpp), called first in `Resolve`: one source target
  must own the whole EDRAM span; the rectangle in the target's pixels comes from the resolve's EDRAM base and
  offsets; every texture at the destination page (`TextureCache::VrTexturesAt`) that is 2D, tiled, scaled-resolve and
  the resolve's 32-aligned size gets a dispatch (a depth resolve's dwords may be read as k_8_8_8_8, k_24_8 or
  k_24_8_FLOAT: the texture's format picks the conversion); any other texture there keeps the memory path
  (`vr_direct_memory_needed_`). Partial resolves (the shadow atlas in quarters) are written at their offset, only
  while the memory is written too and the texture is not outdated. Exponent bias, red/blue swap, MSAA sample
  select (2x-as-4x: samples 0 and 3) are applied.
- The GLSL (`VrDirectResolveGlsl`, compiled at run time with the SDK's glslang) by variant: colour float or integer
  transfer view (R16G16B16A16 / R32 / R16G16 / R32G32 UINT), 1/2/4 samples, destinations rgba16f / rgba8 / r32f /
  r8 / depth+stencil packed into rgba8 bytes / 20e4 depth decoded to r32f / 24-bit depth as unorm r32f; the 20e4
  encode and decode transcribed from `SpirvShaderTranslator::PreClampedDepthTo20e4` / `Depth20e4To32`.
- Textures: `VK_IMAGE_USAGE_STORAGE_BIT` on scaled-resolve 2D textures, a storage view and a descriptor set per
  texture (`VrGetStorageDescriptorSet`), `Usage::kComputeWrite` (GENERAL). After `MarkRangeAsResolved` outdates the
  texture, `VrMakeTextureUpToDate` clears that, so the fetch loads nothing. The texture is marked eye-dependent
  before its set is written: the right eye's replay (the twin set, layer 1 of the target) writes the twin image.
- `MCLA_VR_DIRECT_RESOLVE`: 0 off, 1 on with the memory still written (default in stereo), 2 the memory left
  unwritten when every texture at the range was written directly (the SDK's stub `direct_host_resolve` dump skipped
  too). `MCLA_VR_DIRECT_NO=bias,partial,depth,colour,fmtN,` leaves kinds to the old path (a bisection).
- Log: `direct resolves N, fallbacks M` per frame, `direct resolve fallback x/frame: why`, `scaled load x/frame:
