## VR (SDK branch `vr`, game branch `vr`; 2026-10-24)

Run: `mcla.exe --vr=true` (or `MCLA_VR=1`); on the simulator add `XR_RUNTIME_JSON=<simulator json> XRFG_DISABLE_OFXR_BRIDGE=1`. `MCLA_VR_STEREO=0`: mono
(the same picture in both eyes). `MCLA_VR_WORLD_SCALE`: game units per metre (1; RAGE units are metres).

- Camera (`src/vr_camera.cpp`): grcViewport::SetCameraMtx (sub_8217CE80) at 0x82312D3C is the frame's camera origin
  (update thread, matrices BCF25AD0/BCF25B10 for the two buffered viewports BCF25BF0/BCF25FE0); every later
  SetCameraMtx on those viewports re-reads the viewport's stored camera, so posing the origin call (a scratch copy,
  head rotation and position in camera space: rows right, up, back, position) poses them all. The render thread
  draws the buffer a frame later: the pose is kept per viewport and handed to the headset (vr::SetFramePose) at
  that viewport's grcViewport::Perspective (sub_8217D460) from 0x822E5EB8, which also gets the headset's fov
  (symmetric union of the eyes; tangents 1.376 x 1.390 on the simulator). The pose travels with VdSwap
  (OnGameSwap) to the GPU thread's swap packet (OnGpuSwap) and the frame's publication.
- Checking world lock: the simulator shows each eye's image as submitted (no reprojection), so a shot at a head turn
  should be the straight-ahead shot rotated by the turn, at the rendered fov. `vr/rotcheck.py A B axis eye l r u d`
  fits the angle by NCC.
- Stereo (`vr_twins.cpp`): the deferred command buffer replays twice per submission; the right eye's function table
  swaps every handle for its twin (images, buffers, views, framebuffers, descriptor sets, query pools). Twins:
  every allocation in memory the CPU can't see gets one of the same size, and resources bound to it are made again
  and bound at the same offset. Textures are the same in both eyes until loaded from GPU-written pages; descriptor
  sets get a twin only when written with an eye-dependent view or buffer. Sparse shared memory is off in stereo.
  Guest vertex shaders get a push constant: x += P00 * (+-baseline/2) where |w - 1| > 1/1024 (screen-space draws,
  W 1, stay put).
- Performance findings (stereo, free roam): the GPU was mostly idle-busy (SM "93%" at 150 W) with fixed per-command
  cost: drawing everything 4x costs nothing; all draws skipped 56 FPS. 4.5 GB/s PCIe reads: uploads and constants
  were in system memory (ReBAR on: type 4 device-local host-visible; `MCLA_UPLOAD_VRAM=0` reverts). 292 render
  passes for 1314 draws a frame per eye: each shared memory upload ended the render pass with barriers on both
  sides. Uploads to pages nothing earlier in the submission read or the GPU wrote now go to a prologue
  (`MCLA_HOIST_UPLOADS=0` reverts): 39 -> 59 FPS, GPU waits 9.7 -> 0.3 ms. GPU hardware counters need the driver's
  counter permission (admin), not changed.
- Game options in stereo (FPS): shadows off 91, MSAA off 75, full-screen blur off 65, foliage shadows off / fast car
  shadows ~64 (baseline 62-64). The shadow cascades (viewports BD012D40..BD013910) are the largest GPU-thread cost.
- Shared memory (2026-10-25): `clear_memory_page_state` (SDK default on) forgets every CPU-uploaded page at frame end,
  so ~24 MB a frame was copied again (uploads "again" 1.5 GB/s by page state). Off (game default now, as
  `ps5/game/main_ps5.cpp`): 69 MB/s. Hot pages (`shared_memory_hot_page_faults` 2, `hot_page_exact` 0) skip the
  write-watch fault and VirtualProtect for pages rewritten every frame; `shared_memory_hot_page_compare` (SDK, new)
  keeps each hot page's last upload and uploads only changed pages (~175 a frame, ~15% of each changed).
- GPU thread profile tools: `MCLA_VR_COUNT=1` (right eye's command counts, wrapper cycle counts, hot page change
  stats, invalidations by kind), `VULKAN_GPU_TIMING=1` (uploads by region and reason), `MCLA_PROFILE_CALLERS=1`
  (system DLL samples by caller; `callers.py`, `dllsyms.py` in the scratchpad tools).
- Twin layer cost: most descriptor writes reference shadow maps / resolved textures (eye-dependent) so ~2/3 of the
  per-draw sets get twins (inherent to replay). Flat open-addressing maps for handle lookups (+2 FPS); holding the
  lock for the whole right-eye replay made it worse (67 FPS: writers wait), reverted.
- HUD layer: `VR_LOG_FRAME=N` logs frame N's draws (shader hashes, target, blend) and resolves; the frame ends:
  post chain (vs 609F70AC) -> minimap and gauge targets (pitch 240/280) -> composite 1FAB9787 into base 720 pitch
  1280 1x -> two additive overlays -> HUD (AED972BB, 88F61743 x45, blend SrcA/1-SrcA) -> resolve to the frontbuffer.

## HUD flicker and transfers (2026-10-26/27 night)

- HUD split race (SDK 3a3db35): VrHudDraw -> SplitFrame refused when `swap_poses` was empty. The GPU thread executes
  the ring as the game writes it, so a frame's HUD draws often run before the game's VdSwap (OnGameSwap) queues the
  frame's pose; its swap packet (OnGpuSwap) can only come after. Empty queue = pose still to come; a known unposed
  front is still refused. Log line every 600 frames: `VR HUD: last 600 frames: split, scene not split, HUD without a
  scene, HUD draws before the split into a multisampled target / another pitch, after the split to another target,
  split failed`. The 600/600 "before the split into a multisampled target" seen on some drives are offscreen (MSAA is
  off in the scene with DLSS): not in the picture.
- Test tools (scratchpad `mc/`): `mcfl.sh` (drive + head sway via `headsway.py`, prints the counters and the
  simulator's ui_flicker_status), `mcburst.sh` (64-frame simulator bursts at a held yaw while driving; `ringcount.py`),
  `mcperf.sh` (uncapped drive, FPS lines and nvidia-smi), `cutab.sh` (cutout on/off/on in one parked session).
- D3D's clear quad (VS 1E6883FCCDE1F688): rectangle list, 3 vertices of 7 floats (x y z r g b a), screen space
  (VTE x/y off), pixel centres at integers; scissor 8192 tall but the pitch wide; clears in strips (e.g. x 480-512
  then 0-480), often through a 4x surface over the target's EDRAM (pitch 640 4x for the 1280-wide scene depth;
  depth-only clears use EDRAM mode kDepthOnly). Per 600 frames ~12,700 clear quads, ~5,700 with transfers.
- Clear cutout (SDK 23be5e5): VrClearCutout (command processor: the rectangle and the targets written whole) ->
  VulkanRenderTargetCache::VrSetClearCutout; Update holds the transfers back (vr_pending_*) while following clear quads
  on the same targets grow the rectangle, then VrFlushPendingTransfers does them with it as the cutout
  (Transfer::GetRectangles' resolve-clear cutout). Flushed at the next other Update, Resolve, ClearCache and before
  the submission's EndRenderPass. Log line: `VR clears: no cutout (...), cutout N; with transfers: held, grown, not all
  targets; transfers held / done tiles`. Off: MCLA_VR_CLEAR_CUTOUT=0 or %TEMP%\mcla_cutout_off (live).
- Cost split at 2x4 (19.5 ms stereo before): mono 9.2 ms; transfers ~5 ms (VULKAN_SKIP_TRANSFERS=1: 69 FPS; skipping
  only those at clear quads, unsafe: 62.7); shadows ~3.3 ms; DLSS ~1 ms an eye. The VULKAN_GPU_TIMING zones put 93%
  in "transfers": wrong, do not use them for splits.
